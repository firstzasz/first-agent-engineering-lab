1: # RelayBoard Domain Glossary
2: 
3: Status: FROZEN FOR PILOT
4: 
5: Date frozen: 2026-10-06
6: 
7: This glossary defines the base domain shared by S01, S02, and S04.
8: 
9: It intentionally does **not** define the semantics of pausing a Job. Those semantics are the ambiguity under test in S02.
10: 
11: ## Job
12: 
13: A configured unit of work that may produce Runs.
14: 
15: A Job has:
16: 
17: - a stable id;
18: - a display name;
19: - an enabled/disabled scheduling state;
20: - a retry policy;
21: - zero or more alert rules.
22: 
23: ## Run
24: 
25: One execution of a Job.
26: 
27: A Run has a stable id and one terminal outcome:
28: 
29: - succeeded;
30: - failed.
31: 
32: A Run may contain one or more Attempts.
33: 
34: ## Attempt
35: 
36: One try within a Run.
37: 
38: The first try is attempt 1.
39: 
40: A failed Attempt may produce another Attempt when the Job's RetryPolicy permits it.
41: 
42: Attempts are not separate Runs.
43: 
44: ## RetryPolicy
45: 
46: Rules that determine the maximum number of Attempts for a Run.
47: 
48: For the pilot fixture, retry behavior must be deterministic.
49: 
50: A retry does not create a new Run id.
51: 
52: ## AlertRule
53: 
54: A rule that can emit an Alert after a Run reaches a terminal outcome.
55: 
56: For the pilot, the relevant rule is a failure alert.
57: 
58: The alert is associated with the Run, not with an individual Attempt.
59: 
60: ## Alert
61: 
62: A synthetic notification emitted by an AlertRule.
63: 
64: No real external messaging service is used.
65: 
66: Each Alert records enough synthetic data for tests to determine which Run caused it.
67: 
68: ## Dashboard
69: 
70: A minimal operator-facing view of Jobs and recent Runs.
71: 
72: The Dashboard exists partly to provide a real user-facing surface for tiny-change and later verification experiments.
73: 
74: ## Scheduler
75: 
76: The component that determines whether a scheduled Job should start a new Run.
77: 
78: Its exact implementation is fixture detail, not a domain term.
79: 
80: ## Manual run
81: 
82: A Run explicitly requested by an operator/API call rather than started by the scheduler.
83: 
84: ## Pause
85: 
86: Not defined in the base glossary.
87: 
88: S02 intentionally asks the treatment to introduce pause behavior while several product semantics remain unresolved.

33:         run = self.store.get_run(run_id)
34:         if run.status != "running":
35:             raise RunAlreadyTerminal(run_id)
36: 
37:         job = self.store.get_job(run.job_id)
38:         attempt = self.store.add_attempt(run_id, succeeded)
39: 
40:         if succeeded:
41:             self.store.set_run_status(run_id, "succeeded")
42:             return "succeeded"
43: 
44:         if attempt.number < job.max_attempts:
45:             return "retry"

48:         self._emit_failure_alert(run_id)

52:         run = self.store.get_run(run_id)

56:             job.id,
