## Invocation and routing

1. Read TASK.md and the core Poteto Mode source. State the task classification and checkable done predicate. For changed/new behavior use Feature. For a reported defect use Bug fix. For a narrow mechanical change take the smallest justified route; retain nonapplicable playbook steps with reasons.
2. Read applicable bundled leaf principles before applying or citing them. Core bindings include laziness-protocol, model-the-domain, prove-it-works, fix-root-causes, test-behavior-not-implementation, sequence-verifiable-units and never-block-on-the-human. Do not apply another arm's method.
3. Ground nontrivial work with How. Simple scope can be traced directly by the lead, which is the declared serial port of its single explainer. Cross-function design invokes Architect: write two structurally distinct sketches, screen against bundled red flags, compare interface depth, choose and record synthesis using the bundled rationale template. Two written sketches can be produced serially by the lead; this is a declared reduction of native parallel design exploration. If fresh helper review would materially improve the choice, use a serial same-model helper.
4. Before nontrivial multi-step implementation record all four throughput items: blocking first steps, independent workstreams, shared mutable state, smallest safe decomposition. Keep an item with n/a and reason where it does not apply.
5. For feature/bug implementation delegate a specific bounded code-writing scope to one fresh serial Codex helper. The lead stays responsible for design, review and verification. A truly mechanical one-file edit can be owned directly with an explicit skip reason and separate fresh review, a declared Codex-port exception. Helpers may not themselves spawn helpers; all operate in the same run area serially. If delegation tools fail, stop and report host failure rather than quietly turning this into a native-method claim.
6. For bugs, reproduce the stated symptom on the real public surface before changing production code. Generate falsifiable hypotheses, narrow with observed runtime evidence, add targeted instrumentation when useful, and confirm the mechanism. Use the bundled TDD skill where a cheap meaningful local target exists: failing check before fix, then passing original-surface check. Keep failing-test-first history where practical. Inconclusive or wrong-surface verification is recorded, never called pass.
7. For features, discover empirical facts from the workspace; classify questions before asking. Genuine product/preference decisions go to the operator. The pilot task is not a blanket authorization to invent unasked product behavior. Record the chosen data shape before writing stateful logic; use surgical changes and verified small units.
8. Verify the original task surface, focused tests and full public suite. Review the diff as lead and obtain one fresh serial helper's scoped code/evidence review before completion; a separate helper may combine diff and trail review. This substitutes fresh same-model review for the native cross-model review. Correct public-review issues before freezing, without hidden evaluation.
9. Use the bundled Show me your work format for nontrivial/unattended decisions: append-only TSV with ts, phase, decision, why, evidence, result. Paths must resolve inside this run. No native transcript directory is available; audit against captured commands, public logs and visible checkpoints. Do not claim a full raw transcript when none was exported.
10. Commit the candidate locally on its run branch. End with what changed, design/root cause where applicable, actual failing/passing evidence, throughput checkpoint, open decisions and Attention review flags. Native Opening a PR is replaced by handing the immutable local commit and evidence to the orchestrator.
